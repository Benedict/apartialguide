# A Partial Guide

A text "street view" of Addiscombe, Croydon. Its name is A Partial Guide. One narrator, Guide, describes the place from open data, and its confusion is earned by that data. It is an art piece, not a game. The spec lives in the project doc "Addiscombe Narrator: spec sketch".

## Hard rules

- Never invent a fact. Guide speaks only from facts a source adapter returned. Phrases around the facts are Guide's; nouns, names, numbers and dates come from facts.
- Every fact carries provenance: source, subject, observed date.
- Guide never names a source or who kept an account (no "Wikidata", no "Food Standards Agency"): Guide alludes to them only by what they do (`keepers.ts`: "those who inspect kitchens", "those who draw the wards"), or says "another account". The sources are credited on the About page, as their licences ask. Prose that names one is not stored or shown (`namesNoSource`), unless the name is also one of the map's own facts there (a tram's operator).
- Never repair data. Broken values ("est Bank") are spoken as found.
- Never edit OpenStreetMap. Gaps stay as found.
- Never call public Overpass, or any OSM API, from the app. Snapshots are taken by hand with `npm run snapshot`.
- Live sources are asked from the reader's browser, for the map's own places, never the reader's location, and say nothing without an answer in time: today's weather and air (`src/lib/browser/sky.ts`, Open-Meteo) and departures at the map's bus and tram stops (`src/lib/browser/transit.ts`, TfL: buses by the NaPTAN code the map gives, tram stops found by their mapped name). The map drawn with `gps` on a wide screen (MapLibre GL JS from jsDelivr, pinned; OpenFreeMap tiles) is the third, centred on where the map puts the stop. They work where the page is served normally, not in the claude.ai preview.
- Write the failing scenario or test before the code.
- Real places come only from dated snapshots in `data/snapshots/`. Test fixtures are synthetic and must not pose as real Addiscombe data.

## Commands

- `npm test`: unit tests (Vitest), then acceptance scenarios (Cucumber).
- `npm run test:acceptance`: Gherkin in `features/`. `@snapshot` scenarios run only once the snapshot file exists; `@icebox` and `@later` never run.
- `npm run lint`, `npm run check`: Prettier, ESLint, svelte-check.
- `npm run dev`: needs `SNAPSHOT_PATH` (see `.env.example`).
- `npm run narrate`: writes prose ahead of time into `NARRATION_PATH` (needs `ANTHROPIC_API_KEY`, capped by `NARRATE_LIMIT`). The Narrate workflow runs it on GitHub by hand, with the key as a repository secret.
- `npm run smoke`: opens the exported page (`EXPORT_PATH`) in Chromium with outside requests refused, and fails unless Guide speaks and the tour begins. CI and the Pages workflow run it.
- `npm run map-check`: opens the exported page wide with the network allowed and waits for the `gps` map; CI runs it without failing on it, as it depends on others' servers.
- `npm run export` refuses a world in which Guide would say undefined, null or NaN (`wordsAmiss`).
- `npm run export`: writes the whole game as one self-contained HTML page (`EXPORT_PATH`, default `build/export/addiscombe.html`) from `SNAPSHOT_PATH`, `START_AT` and any `NARRATION_PATH`.
- `BBOX=minLon,minLat,maxLon,maxLat npm run snapshot` (or `AROUND_WAY=<id> RADIUS_M=<m>`): writes `data/snapshots/addiscombe-<date>.json`. Editing `data/snapshots/request.env` and pushing runs the Snapshot workflow, which takes one on GitHub and commits it. `AROUND_PLACE=<name> RADIUS_M=<m>` takes the box around the map's own point for a place (OSM has no outline for Addiscombe), and `AREA=<name pattern>` the box around matching boundaries; both fetch from Overpass, as a whole area is beyond the OSM API's limit. With `AS_OF=<dates>` it fetches past maps from Overpass into `data/history/`, by default for the newest snapshot's box; editing `data/history/request.env` runs the History workflow. The export carries the world gzipped, opened in the browser.
- The Pages workflow publishes the export to GitHub Pages on every push to main (and by hand): the one place live weather can be seen, since the claude.ai preview blocks outside requests.
- `SOURCES=hygiene,… npm run records`: writes `data/records/<prefix>-<date>.json` for each source, the box being the newest snapshot's; each source's parser lives in `src/lib/server/sources/`. Editing `data/records/request.env` runs the Records workflow.
- `BBOX=… npm run wikidata`: writes `data/wikidata/addiscombe-<date>.json`, the items the snapshot links to and those Wikidata places in the box. Editing `data/wikidata/request.env` runs the Wikidata workflow. It is never called from the app.

## Layout

The core in `src/lib/core/` is plain TypeScript with no framework imports, so Cucumber can load it directly.

- `osm.ts`: snapshot format and index.
- `adapters/`: one `SourceAdapter` per source, each returning `Fact`s (`facts.ts`). `history.ts` compares past maps (`HISTORY_DIR`) with the current one: what has gone becomes `was:` facts, an older name a `was:name` fact. `wikidata.ts` is another account (`WIKIDATA_DIR`): facts about what the map links to, who a street is named for, and things only Wikidata places here; Guide never gives them as the map's. `records.ts` turns other sources' records (`RECORDS_DIR`) into facts marked `elsewhere`, attached to the thing the map links them to, at their address, or of their name close by, else standing alone; `render/records.ts` holds what Guide says of each: short sayings (hygiene rating, listing, plaque) in rooms, the rest (planning applications, sales, crime) on examining a thing or street. A record stands alone only with a name. A store may also carry `areas` (ONS wards, `areas.ts`): each stop is put in the ward it lies in, and the game tells a step that crosses from one ward to another, by another account. Sources: FSA food hygiene, planning.data.gov.uk listed buildings and protected trees, London Planning Datahub applications, Open Plaques, HM Land Registry Price Paid, police.uk street-level crime. OpenBenches benches and their inscriptions, each going with a bench the map has within 15 m (a record's `near`) or standing alone by its words. NBN Atlas wildlife sightings (latest of each kind per patch, open licences only), ended postcodes from the ONS Postcode Directory, and companies on the Companies House register by address. `data/records/use.env` names fetched sources the walk leaves out (`LEAVE_OUT=`); everything else in the folder is used, by the Pages and Narrate workflows alike. GLA London Datastore public realm trees, counted per street (in Addiscombe only TfL's highway trees are listed; the council's are not). `tfl.ts` reads TfL's arrivals as facts, `render/departures.ts` says the soonest three. `weather.ts` reads today's weather, as the reader's browser fetched it; it is outside perception, and no past day's weather is ever spoken. `heavens.ts` works out where the sun and moon stand now over the map's place (`astronomy.ts`, after SunCalc); calculated in the browser, it needs no answer, and like the weather is only ever for now.
- `stops.ts`: street graph to stops. Junctions plus corridor stops at most `spacing` metres apart; exits named by compass point.
- `perception.ts`: facts within reach, occluded by mapped buildings. `narrator.ts` tells something addressed to a street that does not meet the stop only within 12 m, and the template tells things in the order they lie along the street they are addressed to, its house numbers rising.
- `tensions.ts`: conditions in the data (fragment, dated, gone, renamed, sparse, dense).
- `slippage.ts`: tensions to a `NarrationPlan` of beats and effects.
- `scene.ts`: places a plan in the network: streets here, what lies either side, where each exit leads.
- `render/`: `Renderer` port, scene to `Room` (title, paragraphs, things to examine). `AdventureRenderer` is the template, writing each paragraph also as labelled `parts` (where, street, setting, thing, frame, exits) so the engine can leave out what the reader heard at the last two places, say "Further along" on the same street, and turn its framing lines; `CachedRenderer` uses prose written ahead of time, keyed by `promptKey(buildPrompt(scene))`, and falls back to the template. `prompt.ts` holds Guide's voice and the reference page: five writers, each with one part (Wainwright the route, Defoe the record, Sinclair the layers, Auster chance, Blake the cadence), with at most one sentence a place reaching for meaning, only with the facts' nouns; the model gets the map in words (`mapWords`, `plainKind`), never raw tags; bump `PROMPT_VERSION` when it changes.
- `narration.ts`: `narrateWorld` writes prose ahead of time through a `ProseModel` port; prose that repairs a broken name is not stored. Each stop is written with the prose already written for the stops one step away, so neighbours do not repeat each other; that context is not part of the key. `src/lib/server/anthropic.ts` is the Claude adapter; tests use `testing/recorded.ts`.
- `narrator.ts`: wires the pipeline.
- `adventure/`: `compileWorld` narrates every stop ahead of time; `parser.ts` and `engine.ts` play it from a prompt. The game opens with Guide's introduction, an account of what Guide carries from the world's `about` ledger (named streets, places, the oldest record, how many other accounts, the wards the map runs into; every figure the data's), and offers the tour, which begins at `START_AT`. Each compiled stop keeps the broken names it speaks; the engine carries them along the walk and, by chance, brings one back out of place (at least four moves on, never where it was found, once each, two a walk at most), never saying where it came from. Each stop also keeps the distinctive words in its names (`terms`: a word in three names of the map or fewer, not a generic place word); by chance, two names met in different places that share one are set side by side (“Havelock Road”. Earlier, “Havelock Hall”.), twice a walk at most, never explained.

`src/lib/site/sources.ts` lists every source with its terms: the About page credits them from it, and the Settings page offers a choice for each live one (`browser/settings.ts`, kept in the reader's browser; turned off, nothing is asked of it). The exported page holds the walk, About and Settings as views of one page, its height fitted to the visual viewport so an on-screen keyboard never covers the prompt. `gps` gives where the map puts the stop and a link to it on Google Maps, never the reader's own position. Ideas for later phases are in `BACKLOG.md`.

The engine keeps classic conventions: a place in full the first time and briefly on return (`look` tells it in full; `verbose`/`brief`), a status line (`status()`: place, moves, metres walked), `z`, `g`, `i`, `xyzzy`. The reader carries names, never things: `take` a broken name or a thing's name, `drop` it at another stop, where it lies until taken again; taken names may come back like fragments. The goal is distance: metres between where the map puts each stop, with marks (250 m, 500 m, 1 km, 2 km…) told once passed, and `score`. Replies may carry `actions` (the tour is a button) and `map`. Walks are saved in five slots (`save 1`–`save 5`, `restore`, offered as buttons) and keep themselves in an `auto` slot after every command, so a page closed mid-walk offers "Continue the walk"; `adventure/saves.ts` holds the plain-data `SavedWalk` and the `SaveStore` port, `browser/saves.ts` the browser's keeper. A walk saved on another map (by date, start and stop count) is refused; weather is never saved, as it is only ever for now.

The web reader is SvelteKit (`src/routes/`): a text adventure with a `>` prompt, playing the compiled world in the browser. Guide speaks to the reader as "you". Configuration comes from environment variables only.

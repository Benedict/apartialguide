# A Partial Guide

A Partial Guide is a text adventure of the real world, built from open data. It starts with Addiscombe, Croydon. One narrator, Guide, describes each place from the data alone, and its confusion is earned by that data. It is psychogeography done with data: a walk read through the records others keep of a place, with drift and chance in it, but the reader is never told so; the copy says plainly what it is, and the walk shows the rest. The spec lives in the project doc "Addiscombe Narrator: spec sketch".

## Hard rules

- Never invent a fact. Guide speaks only from facts a source adapter returned. Phrases around the facts are Guide's; nouns, names, numbers and dates come from facts.
- Every fact carries provenance: source, subject, observed date.
- Guide never names a source or who kept an account (no "Wikidata", no "Food Standards Agency"): Guide alludes to them only by what they do (`keepers.ts`: "those who inspect kitchens", "those who draw the wards"), or gives what they keep as hearsay (`render/hearsay.ts`: "They say…", "It is said that…", "Someone wrote down that…"), save the words on a plaque or a bench, which are read as they are ("a plaque: “…”", "a bench. On it: “…”"), never "another account", which stored prose may not say either. The sources are credited on the About page, as their licences ask. Prose that names one is not stored or shown (`namesNoSource`), unless the name is also one of the map's own facts there (a tram's operator).
- Never repair data. Broken values ("est Bank") are spoken as found.
- Never edit OpenStreetMap. Gaps stay as found.
- Never call public Overpass, or any OSM API, from the app. Snapshots are taken by hand with `npm run snapshot`.
- Live sources are asked from the reader's browser, for the map's own places, never the reader's location, and say nothing without an answer in time: today's weather and air (`src/lib/browser/sky.ts`, Open-Meteo) and departures at the map's bus and tram stops (`src/lib/browser/transit.ts`, TfL: buses by the NaPTAN code the map gives, tram stops found by their mapped name). The map drawn with `gps` on a wide screen (MapLibre GL JS from jsDelivr, pinned; OpenFreeMap tiles) is the third, centred on where the map puts the stop. `use the camera` shows what TfL's JamCam nearest where the map puts the stop last saw (within 1.5 km; when, from the picture's Last-Modified), and `look up` tells the weather and the planets (Astronomy Engine, worked out), then the satellites above the roofs (CelesTrak's elements, kept six hours, worked out with satellite.js) and the aircraft overhead (adsb.lol, through the flights function, `functions/flights/`, deployed separately as adsb.lol lets no other site's page read it; the page is built with `FLIGHTS_URL`, and without it asks after no aircraft) (`src/lib/browser/live.ts`). Without an answer the camera says only "Nothing happens." `look beyond` tells what others keep that the map does not show, within 6 km of the stop, nearest first, three at most, as hearsay (`render/beyond.ts`; a store's `beyond`, such as Digital Britannia's Roman roads and sites, `SOURCES=britannia BRITANNIA_DIR=…`, read from its GeoJSON layers downloaded by hand). It is never told in a room, only when the reader looks beyond; with nothing kept near enough, Guide owns to not knowing. They work where the page is served normally, not in the claude.ai preview.
- Write the failing scenario or test before the code.
- Real places come only from dated snapshots in `data/snapshots/`. Test fixtures are synthetic and must not pose as real Addiscombe data.

## Commands

- `npm test`: unit tests (Vitest), then acceptance scenarios (Cucumber).
- `npm run test:acceptance`: Gherkin in `features/`. `@snapshot` scenarios run only once the snapshot file exists; `@icebox` and `@later` never run.
- `npm run lint`, `npm run check`: Prettier, ESLint, svelte-check.
- `npm run dev`: needs `SNAPSHOT_PATH` (see `.env.example`).
- `npm run narrate`: writes prose ahead of time into `NARRATION_PATH` (needs `ANTHROPIC_API_KEY`, capped by `NARRATE_LIMIT`). The Narrate workflow runs it on GitHub by hand, with the key as a repository secret.
- `npm run smoke`: opens the exported page (`EXPORT_PATH`) in Chromium with outside requests refused, and fails unless Guide speaks and the tour begins. CI and the Pages workflow run it.
- `npm run map-check`: opens the exported page wide with the network allowed and waits for the `gps` map; CI runs it without failing on it, as it depends on others' servers.
- `npm run export` refuses a world in which Guide would say undefined, null or NaN (`wordsAmiss`).
- `npm run export`: writes the whole game as one self-contained HTML page (`EXPORT_PATH`, default `build/export/addiscombe.html`) from `SNAPSHOT_PATH`, `START_AT` and any `NARRATION_PATH`. With `SITE_DIR` it writes the site instead: `index.html` carrying only the world's head, and the world in tiles about `TILE_M` metres across (default 300; `adventure/tiles.ts`, `tileWorld`), each stop named by its tile so an exit says where to find what it leads to. The page fetches the tiles as the walk reaches them (`tiledWorld`), opening before each command the places it `needs` and fetching the way ahead while the reader reads, so it opens at once however large the map. `SITE_DIR=… npm run smoke` serves the site over http and checks it plays; the single page still plays in the claude.ai preview.
- `BBOX=minLon,minLat,maxLon,maxLat npm run snapshot` (or `AROUND_WAY=<id> RADIUS_M=<m>`): writes `data/snapshots/addiscombe-<date>.json`. Editing `data/snapshots/request.env` and pushing runs the Snapshot workflow, which takes one on GitHub and commits it. `AROUND_PLACE=<name> RADIUS_M=<m>` takes the box around the map's own point for a place (OSM has no outline for Addiscombe), and `AREA=<name pattern>` the box around matching boundaries; both fetch from Overpass, as a whole area is beyond the OSM API's limit. With `AS_OF=<dates>` it fetches past maps from Overpass into `data/history/`, by default for the newest snapshot's box; editing `data/history/request.env` runs the History workflow. The export carries the world packed (`adventure/packed.ts`: each thing once however many stops see it, paragraphs left to the parts that spell them out), gzipped, and opened in the browser after Guide has begun: the page carries the introduction's ledger apart (`introduction`), so Guide speaks at once, and offers the tour (`offer`) once the world is open and today's weather has come or not.
- The site (`SITE_DIR`) is the microsite at its root (`server/landing.ts`: what the piece is, the tour's first place as it plays, built at noon on the map's date, the ledger's figures, things to try, and "Begin the walk"), and the walk at `walk/`. `GA_MEASUREMENT_ID` (a repository variable) adds Google Analytics to both, counted only once a reader says yes (`browser/analytics.ts`: a strip asks once, Settings can change the answer; nothing of Google's loads before a yes), and then only the page, the kind of each command (`parse(text).verb`) and distance marks, never what is typed; without it, nothing is sent and the About page says so. The single page has no analytics.
- The Pages workflow publishes the site, the microsite and the walk in tiles, to GitHub Pages on every push to main (and by hand): the one place live weather can be seen, since the claude.ai preview blocks outside requests.
- `SOURCES=hygiene,… npm run records`: writes `data/records/<prefix>-<date>.json` for each source, the box being the newest snapshot's; each source's parser lives in `src/lib/server/sources/`. Editing `data/records/request.env` runs the Records workflow.
- `BBOX=… npm run wikidata`: writes `data/wikidata/addiscombe-<date>.json`, the items the snapshot links to and those Wikidata places in the box. Editing `data/wikidata/request.env` runs the Wikidata workflow. It is never called from the app.

## Layout

The core in `src/lib/core/` is plain TypeScript with no framework imports, so Cucumber can load it directly.

- `osm.ts`: snapshot format and index.
- `adapters/`: one `SourceAdapter` per source, each returning `Fact`s (`facts.ts`). `history.ts` compares past maps (`HISTORY_DIR`) with the current one: what has gone becomes `was:` facts, an older name a `was:name` fact. `wikidata.ts` is another account (`WIKIDATA_DIR`): facts about what the map links to, who a street is named for, and things only Wikidata places here; Guide never gives them as the map's. `records.ts` turns other sources' records (`RECORDS_DIR`) into facts marked `elsewhere`, attached to the thing the map links them to, at their address, or of their name close by, else standing alone; `render/records.ts` holds what Guide says of each: short sayings (hygiene rating, listing, plaque) in rooms, a plaque always noticed however crowded the stop (`slippage.ts`) and a stop made beside it, as beside a named place (`landmarks`), the rest (planning applications, sales, crime) on examining a thing or street. A record stands alone only with a name. A store may also carry `areas` (ONS wards, `areas.ts`): each stop is put in the ward it lies in, and the game tells a step that crosses from one ward to another, by another account. Sources: FSA food hygiene, planning.data.gov.uk listed buildings and protected trees, London Planning Datahub applications, Open Plaques, HM Land Registry Price Paid, police.uk street-level crime. OpenBenches benches and their inscriptions, each going with a bench the map has within 15 m (a record's `near`) or standing alone by its words. NBN Atlas wildlife sightings (latest of each kind per patch, open licences only), ended postcodes from the ONS Postcode Directory, and companies on the Companies House register by address. Environment Agency flood zones and recorded floods, as overlay `areas`: the engine says when a step enters or leaves one (none lie in Addiscombe's box). Two sources need keys as repository secrets, and fetch nothing without them: energy certificates (`EPC_EMAIL`, `EPC_API_KEY`), the latest for each address, saying when a house was built and how it is rated, on examining it; and Geograph photographs (`GEOGRAPH_API_KEY`), the latest in each patch of about 100 m, standing alone by their titles. `data/records/use.env` names fetched sources the walk leaves out (`LEAVE_OUT=`); everything else in the folder is used, by the Pages and Narrate workflows alike. GLA London Datastore public realm trees, counted per street (in Addiscombe only TfL's highway trees are listed; the council's are not). `tfl.ts` reads TfL's arrivals as facts, `render/departures.ts` says the soonest three, headed by the way the stop serves as TfL gives it ("Parkview Road, towards East Croydon Or West Croydon"), else its letter (TfL's, or the map's `local_ref` when nothing is due), so two stops of one name either side of a road are told apart. `weather.ts` reads today's weather, as the reader's browser fetched it; it is outside perception, and no past day's weather is ever spoken. `heavens.ts` works out where the sun and moon stand now over the map's place (`astronomy.ts`, after SunCalc); calculated in the browser, it needs no answer, and like the weather is only ever for now. A street's lighting is said by the hour the same way (`render/lighting.ts`), with licence Benedict allows: a street the map says is lit has street lamps along it, and the sun now says whether they are out, coming on or lighting the way ("Street lamps light the way."); an unlit street has none. The licence is in the hour only, never in a lamp's being at a spot (the map has 8 lamps of its own; they are "a street lamp"). The template marks the sentence (`lit` on its part) and the engine says it on arrival and on `look`, two ways each, while the prompt keeps the map's "Lit at night".
- `stops.ts`: street graph to stops, where a walker would stop: where streets and paths meet, where one ends, where a street changes its name, beside named places along a street (those within 60 m of each other sharing one), and on a long street at most `spacing` metres apart (`STOP_SPACING_M`, default 150). Driveways, parking aisles, pavements and crossings make no stop (`isMinor`), nor does an unnamed way that leads a few metres to nowhere, nor an unnamed service road that leads nowhere at all; a junction drawn as several nodes within 15 m is one stop. Where pavements and crossings alone join one part of the network to another (across a main road no one walks along), the shortest such way is kept (`bridge`), so no street is cut off; a gap the map leaves stays. Each stop takes in its `stretch`, its half of each street to the next stops, and `narrator.ts` perceives from all of it. Exits named by compass point.
- `perception.ts`: facts within reach, occluded by mapped buildings. `narrator.ts` tells something addressed to a street that does not meet the stop only within 12 m, and the template tells things in the order they lie along the street they are addressed to, its house numbers rising.
- `tensions.ts`: conditions in the data (fragment, dated, gone, renamed, sparse, dense).
- `slippage.ts`: tensions to a `NarrationPlan` of beats and effects.
- `scene.ts`: places a plan in the network: streets here, what lies either side, where each exit leads.
- `render/`: `Renderer` port, scene to `Room` (title, paragraphs, things to examine). `AdventureRenderer` is the template, writing each paragraph also as labelled `parts` (where, street, setting, thing, nearest, frame, exits) so the engine can leave out what the reader heard at the last two places (framing lines included), say "Further along" on the same street, and turn its framing lines and its three forms of the opening (`whereForms`), never the same form twice in a row. It counts plain things of one kind ("Two buildings: …"), gives a house its kind and a building its storeys where the map does, leaves the usual surface unsaid in a room (asphalt, on nearly every street; on examining a street it is "tarmac", the word a walker here would use), telling only one out of the ordinary ("Gravel underfoot."), says how far each exit runs to the next street, and at a quiet stop (things in view, none named; never an empty one) the nearest named thing within 400 m (`Scene.nearest`); `CachedRenderer` uses prose written ahead of time, keyed by `promptKey(buildPrompt(scene))`, and falls back to the template. `prompt.ts` holds Guide's voice and the reference page: five writers, each with one part (Wainwright the route, Defoe the record, Sinclair the layers, Auster chance, Blake the cadence), with at most one sentence a place reaching for meaning, only with the facts' nouns; the model gets the map in words (`mapWords`, `plainKind`), never raw tags; bump `PROMPT_VERSION` when it changes.
- `narration.ts`: `narrateWorld` writes prose ahead of time through a `ProseModel` port; prose that repairs a broken name is not stored, nor prose that says what its facts do not (`render/founded.ts`, `unfounded`: a number, a quotation or a capitalised word inside a sentence that the stop's facts, as words, do not hold), nor prose that reuses a run of six words of Guide's own already in two stored pieces for the current stops (the facts' own words may recur; pieces kept for stops the map no longer has do not count). `NARRATE_ONLY=busier` narrates only stops whose data has something going on (`busier.ts`: a named thing, another account, something gone, a broken name); the template carries the rest. Each stop is written with the prose already written for the stops one step away, so neighbours do not repeat each other; that context is not part of the key. `src/lib/server/anthropic.ts` is the Claude adapter; `src/lib/server/written.ts` reads prose written in a Claude Code session instead (`npm run narrate:prompts` writes the next stops' prompts to `build/narrate/prompts.md`; the prose goes into a JSON file of key to prose, and `PROSE_FROM=… npm run narrate` puts it through the same guards), so a Max subscription can narrate without an API key; `src/lib/server/openrouter.ts` asks other providers' models through OpenRouter (`NARRATOR_PROVIDER=openrouter`, `NARRATOR_MODEL`, `OPENROUTER_API_KEY`; providers that keep prompts refused), and `npm run compare` (the Compare models workflow) narrates the same busier stops with several models and reports what the guards refused, storing nothing; tests use `testing/recorded.ts`.
- `narrator.ts`: wires the pipeline.
- `adventure/`: `compileWorld` narrates every stop ahead of time; `parser.ts` and `engine.ts` play it from a prompt. The game opens with Guide's introduction, an account of what Guide carries from the world's `about` ledger (named streets, places, the oldest record, how many other accounts, the wards the map runs into; every figure the data's), and offers the tour, which begins at `START_AT`. Each compiled stop keeps the broken names it speaks; Guide carries one only when the reader asks (`remember X`, `mark down X`, `note X`, `write down X`, or `take X`), never unasked, and by chance brings one carried back out of place (at least four moves on, never where it was found, once each, two a walk at most), never saying where it came from; once one has come back, `i` says Guide is still carrying it and `examine` it says only "A name, as I found it." Each stop also keeps the distinctive words in its names (`terms`: a word in three names of the map or fewer, not a generic place word); by chance, two names met in different places that share one are set side by side (“Havelock Road”. Earlier, “Havelock Hall”.), twice a walk at most, never explained.

`src/lib/site/sources.ts` lists every source with its terms: the About page credits them from it, and the Settings page offers a choice for each live one (`browser/settings.ts`, kept in the reader's browser; turned off, nothing is asked of it). The exported page holds the walk, About and Settings as views of one page, its height fitted to the visual viewport so an on-screen keyboard never covers the prompt; after each command the page shows the newest text, but never scrolls the start of the latest reply (the command typed) above the top (`reveal`), so a reply taller than the screen is read from its start. `gps` gives where the map puts the stop and a link to it on Google Maps, never the reader's own position; `gps on` keeps one map under the status bar, on any screen, moved to each stop as the reader walks (a reply's `follow`), and kept through a saved walk; `gps off` puts it away. Ideas for later phases are in `BACKLOG.md`. What only Benedict can do (keys, decisions, words) is in `TODO.md`.

The engine keeps classic conventions: a place in full the first time and briefly on return (`look` tells it in full; `verbose`/`brief`; `plainly` tells it again from the template alone where prose written ahead of time was told, so the reader can hear both voices at one place, and elsewhere Guide says it has told it plainly already); where a place's prose would tell again at least half the things heard at the last two places (its things as the template keys them), the engine tells that place plainly instead, leaving out what was heard, and prose it does tell counts its things as heard, as the template's do, a status line (`status()`: place, moves, metres walked), `z`, `g`, `i`, `xyzzy`. The reader carries names, never things: `take` a broken name or a thing's name, `drop` it at another stop, where it lies until taken again; taken names may come back like fragments. `route to X` (or `way to X`, `directions to X`, `how do I get to X`) plans the shortest way along the streets to the nearest stop where X is a street or a named thing, matched by its words and the thing's kind (`adventure/route.ts`), and gives it leg by leg; until the reader arrives, or says `route off`, each stop adds the next turn ("Your way to “The Alma Tavern”: south-west (Lower Addiscombe Road)."), and a saved walk keeps it. The reader still walks every step. Now and then (after the first step, then every 8 steps) a reply carries a `hint`, the page's and not Guide's, shown quieter: a command the reader has not used yet (`gps`, `drift`, `route to`, `look up`, …), each at most once, remembered across walks in the reader's browser (`adventure/hints.ts`, the `HintKeeper` port; `browser/hints.ts`), so once every hint is given none comes of its own again; `hint` asks for one at any time, even then or with `hints off`; `hints off` and `hints on`, kept the same way. `drift` (`wander`, `go anywhere`) is the other way of going: Guide chooses the next exit by chance, leaning towards what is odd in the data ahead (a broken name, a distinctive word met before, a place with something going on, a place not yet seen), never doubling back while there is another way, and says only which way ("You drift south-west."), never why; it is a step like any other. The engine plans from a `RouteIndex`, the street network alone, worked out from a whole world, or, on the site, fetched as `routes.json` the first time a way is asked for. The goal is distance: metres between where the map puts each stop, with marks (250 m, 500 m, 1 km, 2 km…) told once passed, and `score`. Replies may carry `actions` (the tour is a button) and `map`. Walks are saved in five slots (`save 1`–`save 5`, `restore`, offered as buttons) and keep themselves in an `auto` slot after every command, so a page closed mid-walk offers "Continue the walk"; `adventure/saves.ts` holds the plain-data `SavedWalk` and the `SaveStore` port, `browser/saves.ts` the browser's keeper. A walk saved on another map (by date, start and stop count) is refused; weather is never saved, as it is only ever for now.

The page looks like a classic adventure: one monospace typeface, light on dark, an inverse status bar on top (place; `Walked:` and `Moves:`). The web reader is SvelteKit (`src/routes/`): a text adventure with a `>` prompt, playing the compiled world in the browser. Guide speaks to the reader as "you". Configuration comes from environment variables only.
